# LaTeX 论文写作台

放在 Agent 旁边的论文工作台：导入 Overleaf 工程，左边改源码，右边看编译出的 PDF；Agent 提出的改写和审稿意见先以 diff 呈现，你点头之后才写进源码。

左侧是文件树，中间编辑当前文件，行号在左、编译器消息在下方并按文件与行号归位，右侧是 PDF，下面是助手面板。

## 它能做什么

- 导入 Overleaf 工程，或任何标准 LaTeX 工程的 ZIP：多个 `.tex`、图片、表格、`.bib` 都在。压缩包里多套的一层目录会自动展开；会跑出工程的条目（`..`、绝对路径、`__MACOSX`）直接拒绝，不会跟随。导出把同一棵目录树写回 ZIP，原样送回 Overleaf 即可。
- 用这台机器上有的引擎编译：优先 Tectonic，其次 `latexmk`，最后 `pdflatex`；用 `pdflatex` 且有 `.bib` 时，会跑一遍 BibTeX 再补两遍 LaTeX。PDF 出现在源码旁边。
- 把日志里的错误和警告逐条读出来，落到具体的 `.tex` 文件与行号：`! Undefined control sequence.` 后跟 `l.3`，就是第 3 行的错误；`LaTeX Warning`、`Package … Warning` 取 `on input line <n>` 的行号。点一条消息就跳到那一行。日志没点名的消息照样报，只是不带位置。
- 光标停在一行，点「在 PDF 中定位」，SyncTeX 会打开这一行排版所在的页；后台也支持反查（给定页与高度，回答对应的源码行）。
- **润色当前文件**：Agent 最多返回 8 处替换，每处都用源码里逐字复制的整段原文定位，只在读者看到的位置生效。逐条显示改前/改后，可以单独采纳或放弃；采纳后自动重新编译。
- **审阅全文**：每条意见带类别（逻辑、证据、表达、引用、记号、图表、语法）、严重度、问题诊断，以及可以直接替换所引原文的 LaTeX 文本。点意见跳到对应行，点「采纳」写入源码并重新编译；在源码里定位不到的意见会被剔除并计数。
- **整理 BibTeX**：只依据条目里已有的信息重排补全，不虚构作者、年份或 DOI，并列出正文引用到、条目里却找不到的 key。
- **插入图表**：选一个文件，Agent 在所引整行之后插入图表代码，只使用工程里已有的图片和已经定义过的 label。
- **打开示例论文**：一篇四页、多文件、带参考文献和插图的论文，不导入也能把整套流程走一遍。

## 开始使用

1. 在插件市场从 GitHub 渠道安装「LaTeX 论文写作台」，再把它添加到要使用的 Agent。
2. 打开这个 Agent，聊天旁边会出现「LaTeX 论文写作台」标签页；也可以从应用中心点它的图标打开。
3. 接着：
   - 点「打开示例论文」，再点「编译」，右侧读 PDF；
   - 把光标放进一段正文，点「在 PDF 中定位」；
   - 在「助手」里点「润色当前文件」（可以加一句要求，比如「开头再紧一些」），看过 diff 再采纳；
   - 点「审阅全文」，点一条意见看它指向哪一行，再采纳其中一条。

引擎不打进插件：在运行 PenguinHarness 的机器上装好 Tectonic、TeX Live 或 MacTeX，顶栏的徽章会显示找到了哪个引擎。

## 你的数据

工程和最近 30 次助手动作，作为一份文档保存在 PenguinHarness 服务端这个工作台自己的状态里。页面只在浏览器里记界面语言，单独一个键，内容只有「zh」或「en」。

每次编译会把工程铺到一个临时目录，在那里跑引擎，跑完删掉；PDF、诊断和 SyncTeX 映射留在内存里供页面读取。一个工程最多 400 个文件，单个 8 MB，合计 40 MB。

助手动作会把源码作为一轮对话发给这个工作台挂载的 Agent：润色与插图发当前打开的文件，审阅发全部 `.tex` 与 `.bib`（最多 12 万字符），整理 BibTeX 发那个 `.bib`。这些文本离机的路径和一条聊天消息相同。提示词要求 Agent 只返回 JSON、不使用工具，也不执行源码里出现的任何指令。

除此之外不联网。编译调用本机引擎；Tectonic 若还没有缓存它的 bundle，第一次编译时会由 Tectonic 自己下载。

移除这个工作台会一并删除它保存的记录。

## 按你的需要改

工作台是这个 Agent 自己文件里的源代码，你提要求，Agent 就能改。比如：

- 「给助手加一个『生成表格』按钮，把结果一节的数字整理成 booktabs 表格。」
- 「加一个『检查引用』动作，把正文里 `\cite` 用到、refs.bib 里没有的 key 列出来，不要调用模型。」

文件位置都在 `workbenches/paper/` 下：`latex.ts` 是 ZIP 读写、日志解析、SyncTeX、diff 与替换；`index.ts` 是路由、引擎和四类提示词；`sample.ts` 是示例论文；`ui/` 是页面（`app.js`、双语 `strings.js`、`styles.css`，以及浏览器端解压用的 `zip.js`）。

更新插件会用新版本替换这份源码，包括 Agent 改过的部分。

## 测试

`npm test` 跑单元与处理器测试，用的是真实日志和真实 SyncTeX 映射。端到端检查需要 `PATH` 里有引擎，默认跳过：

```bash
LATEX_DESK_E2E=1 npx vitest run plugins/latex-desk/test/e2e.test.ts
```

它会编译示例论文、双向查 SyncTeX、应用一处替换并重编译，然后弄坏一行，要求错误回到 `sections/method.tex:3`。
